# Legacy migration

The add-on contains an idempotent compatibility migration for Iron Age Furniture padded benches and padded back benches created by the 1.10 and 1.12 branches.

## Colour contract

- The shared historical block-entity ID is `ironagefurniture:padded_bench_colour`.
- The stable item and block-entity field is `Color`.
- A missing or invalid value means `red`, preserving the currently released red-only format.
- The supported values are `red`, `orange`, `magenta`, `light_blue`, `yellow`, `lime`, `pink`, `gray`, `light_gray`, `cyan`, `purple`, `blue`, `brown`, `green`, `white`, and `black`.
- Successful item conversion removes only the obsolete `Color` custom-data field. Other stack data and the count are retained.

Compatibility blocks are hidden and itemless. Once a loaded chunk is ready, they are replaced with the modern colour-specific block while shared facing, connection, waterlogging, and other compatible block-state properties are retained. Repeated loads make no further changes.

## Retired wood visual fallbacks

These are compatibility choices for Iron Age Furniture entries, not claims that Biomes O' Plenty renamed the upstream woods.

| Retired BOP wood | Modern target |
|---|---|
| Cherry | Vanilla cherry |
| Ebony | BOP hellbark |
| Ethereal | Vanilla warped |
| Eucalyptus | BOP origin oak |
| Mangrove | Vanilla pale oak |
| Sacred oak | BOP origin oak |

Surviving BOP wood names retain their historical `ironagefurniture` IDs. The existing core BOP-cherry alias is deliberately followed through its no-colour vanilla-cherry intermediate before the add-on selects the final colour-specific target.

## Validation and whole-world upgrades

Binary compressed-NBT fixtures generated by the actual 1.10 and 1.12 candidate code cover the released red-only representation and all sixteen forthcoming colours. Automated tests exercise placed-block records, player inventory, nested containers, and dropped-stack representations. A packaged 26.3 server probe additionally proved purple Ebony and red-default Fir placed-block conversion, then proved that a reload performed no second migration.

This compatibility layer runs only after Minecraft can deserialize a world. It does not bypass Mojang's world-version upgrade rules, so it must not be presented as a general direct 1.10/1.12-to-26.3 world converter. Keep the original world backed up and use disposable copies through the normal Minecraft upgrade sequence before installing the 26.3 add-on. The furniture migration itself is independent of the intermediate path once the legacy IDs and `Color` data reach 26.3 intact.
